# Обновление сайта на REG.RU

Основной адрес по указанию заказчика — `https://www.кавергруппачелябинск.рф/`.
Punycode: `www.xn--80aadcflczkii0auambz1a3fsi.xn--p1ai`.

Корневые HTML, CSS, JS и `assets/` остаются единым источником. HTML в репозитории предназначен для демоверсии GitHub Pages: `noindex,nofollow` и демонстрационные адреса метаданных. Действующий `.github/workflows/pages.yml` не меняется.

`python3 ops/build_reg_ru.py` создаёт `dist/reg-ru/staging/`: папку `site/`, архив всех публичных файлов, отдельный небольшой архив HTML/robots/sitemap и закрытый локальный `manifest.json` с SHA-256. Сборка заменяет только метаданные в `<head>`; видимое содержимое, ID песен, ссылки, CSS, JS и медиа сохраняются. Архив содержит `index.html` непосредственно в корне. Исходники, `.git`, переписка, резервные копии и инструменты не входят в архив.

Первичная проверка выполняется с запретом индексации. После успешной проверки публичного HTTPS-адреса команда `python3 ops/build_reg_ru.py --indexable` формирует `dist/reg-ru/live/` с `index,follow`, `Allow: /` в robots.txt, пятью canonical и sitemap.xml. Обе сборки используют HTTPS с www. Существующие каталоги выпусков не перезаписываются: их следует сохранять для отката перед новой сборкой.

Загрузка через уже авторизованную панель ispmanager:

1. Сохранить текущий каталог сайта и настройки DNS/SSL. Сверить папку, назначенную корнем в разделе «Сайты»; не выбирать её по предположению.
2. В «Менеджере файлов» загрузить ZIP в `/releases`, вне `/www` и публичного каталога сайта.
3. Распаковать содержимое архива непосредственно в назначенный корень сайта, с заменой файлов предыдущего выпуска после резервирования. Не создавать дополнительную внешнюю папку.
4. Проверить пять страниц, контакты, галереи, видео и репертуары, HTTPS и отсутствие циклов перенаправления. Сравнить файлы с локальным manifest; для видео проверить размеры и HTTP Range.
5. При первичном запуске после проверки применить небольшой `reg-ru-live-pages.zip` для открытия индексации. В дальнейшем сохранять индексацию уже работающего основного сайта.
6. Убедиться, что HTTP и адрес без www приводят к основному HTTPS-адресу; сертификат покрывает оба имени. GitHub Pages остаётся демонстрационной копией с noindex.

Доступы в Git не хранятся. DNS, сертификат и перенаправления изменяются в существующей панели; повторная первичная настройка при обычном обновлении файлов не нужна. Архивы на сервере хранятся вне корня сайта. Для отката используется сохранённый предыдущий выпуск.

Почтовые и проверочные записи не удалялись. Обе новые записи подтверждены прямым запросом к авторитетным DNS-серверам.

Бесплатный Let's Encrypt выпущен для домена и www. Использовать штатные настройки HTTPS и редиректа с домена без www на www. HSTS пока не включён. Изменения панели применяются с задержкой: успешное сохранение следует подтверждать HTTP-ответами.

При обновлении DNS часть рекурсивных серверов может временно возвращать старый адрес. Старый TTL был 21600 секунд. Отдельно проверять авторитетные записи, публичные DNS и фактический IP HTTP-соединения. Проверка с `curl --resolve` подтверждает файлы на сервере, но не распространение DNS. Проверка с публичным DNS-over-HTTPS без подстановки IP подтверждает доступность через выбранный публичный резолвер.
